# Hangang Runtime

한강 월드의 공용 서버 기반입니다. 호패의 인증, 품계의 권한, 수문장의 네트워크 판정은 각 모듈이 소유합니다.

기본은 각 서버 실행 파일에 버전을 고정해 컴파일하는 정적 링크 Rust
라이브러리입니다. 네 서버는 독립 배포·확장이 가능하며 라이브러리 공유로
요청 경로에 네트워크 호출이 추가되지 않습니다. Linux 릴리즈는 musl을 기본으로
정적 ELF 검증을 통과해야 합니다. 공용 런타임 갱신은 각 소비자의 재빌드와
검증이 필요합니다. DB 기반 인메모리 정책 스냅샷과 도메인 소유 공급자 확장은
계속 런타임에 변경할 수 있습니다.

첫 구현은 gRPC 필수 mTLS, TLS 파일 제한, 동시 연결 2,048개, 연결당 요청·스트림 64개, 헤더 8KiB, 요청 시간 1초, TCP_NODELAY를 공유합니다. 자격 역할, 전체 판정 처리량, 메시지 크기와 스냅샷 판정은 각 서버가 관리합니다.

네이티브 프로토콜, 감독 실행, 리스너 인계와 관측 기능의 공용화는 후속 작업입니다. 각 서버는 계속 독립적으로 배포합니다.

공용 TLS 파서는 네이티브/관리 mTLS 설정에도 사용합니다. serve_https는 관리 HTTP/1.1 연결 2,048개, TLS 핸드셰이크 3초, 헤더 64개·버퍼 32KiB, 헤더 읽기 5초, 연결 수명 300초, 종료 드레인 5초를 제한합니다. 역할·본문 제한은 도메인이 소유하며 네이티브 판정 프로토콜을 대신하지 않습니다.

serve_connections는 TCP 연결 제한과 연결 태스크 소유권을 공유합니다. 실제 접속
주소·TCP_NODELAY를 유지하고 초과 연결을 거부합니다. 지정된 시간 동안 드레인한
뒤 남은 태스크를 취소하고 회수하며 서버 취소도 소유한 태스크를 취소합니다. TLS,
네이티브 프레이밍, 자격, 연결 수명과 판정은 핸들러가 소유합니다. 관리 HTTPS에
적용했으며 네이티브 리스너 적용은 소비자별 검증이 필요합니다. 실제 소켓으로
용량 보존·재사용, 종료와 소유 서버 취소를 검증합니다.

`time::ReceiverClock`은 관측 규약용 Linux `CLOCK_BOOTTIME` 기반입니다.
고정 원점의 tick은 호스트 절전 시간을 포함하고 UTC 시계 이동에는 영향받지
않습니다. 지원하지 않는 플랫폼이나 읽기 실패에서는 다른 시계로 우회하지 않고
거부합니다. 네이티브 시작 코드가 새 0 아닌 CSPRNG 세대를 공급하며, 별도 비공개
인스턴스 표식은 같은 세대 값을 준 다른 시계의 토큰도 거부합니다. 교환 표본은
`LocalDeadline`과 `ReplayRetention`을 구분해 결합하고, 재검증은 집행을 줄이고
보존을 늘립니다. 집행 폐기 자체가 nonce 삭제 권한은 아닙니다. 요청 경로의 mutex,
heap 할당, 벽시계 읽기와 SQL은 없습니다. 테스트 시계 주입은 비공개 테스트 전용입니다.

이 타입은 수치 기반이며 인증된 원천 보고나 권한 capability가 아닙니다.
저장한 단조 좌표 복원, 이전 분산 소유자 fencing, 시계 속도 가정 검증이나 replay
ledger를 구현하지 않습니다. 실제 receipt·클라이언트·ledger 적용은 소비자별
후속 검증 항목입니다.

`time::ElapsedStamp`는 인증 대기를 포함한 원천 증명 나이를 BOOTTIME으로
측정하는 별도 비공개 필드의 표본입니다. 숫자·직렬화 생성자나 더 약한 시계
우회는 없습니다. 호출자는 관련 경계마다 원래 예산을 차감해야 하며, 이 기반을
추가한 것만으로 기존 원천 어댑터의 절전 안전성이 완성되지는 않습니다.


`ReceiverClock::sample_ticks`는 교환 객체 생성·표식 clone 없이 backend 한 번으로
활성 프로세스의 양수 BOOTTIME tick을 읽습니다. 읽기 뒤 폐기를 재확인하고 읽기·
오버플로 실패를 거부합니다. 네이티브 어댑터가 자신의 원천 좌표를 얻을 때 시계 두 번
읽기를 피하지만, 수치 기반일 뿐 원격 시계 인증·권한 부여 기능은 아닙니다.
절전·내림·실패·오버플로·읽기 도중 폐기를 결정적 검사로 확인합니다.
